# Project audit: efficiencies, curve-model enhancements, and model extensibility

**Date:** 2026-09-02
**Scope:** `src/nelson_siegel` (model, analysis, data, webapp), tests, packaging, docs.
**Baseline:** commit `1da48ec` on `main`. 45 tests, 2 failing.

This document records what was found, what was changed in this branch, and an
assessment of whether the codebase is ready to host additional curve models.

---

## 1. Summary

| Area | Finding | Action taken |
|---|---|---|
| Model fitting | `curve_fit` started from a fixed guess in the wrong units (`beta0 = 3.0` for decimal yields); tau frequently stalled on the bound (TIPS global tau came out as exactly `10.0`). | New default `method="profile"`: grid over tau with closed-form betas, multi-start bounded refinement. Deterministic, more accurate, never worse in sum of squared errors than `curve_fit` (tested). Legacy path kept as `method="curve_fit"`. |
| Global tau for history | Estimated from a **single** most-recent curve, so the whole 10-year factor history depended on one day's quotes. | Panel (Diebold-Li) estimate: pooled sum of squared errors over up to 48 evenly spaced curves, profiled over tau. |
| Duplicate downloads | `_estimate_global_tau` re-downloaded the full dataset (a second set of 9 FRED calls per bond type); `/api/snapshot` re-downloaded on every click; the webapp held two independent `DataManager` instances. | Downloads are memoised per `(start, end)` window on each downloader; tau estimation reuses the caller's frame; the webapp shares the analyzer's data manager. |
| FRED latency | 9 (Treasury) + 5 (TIPS) sequential HTTP calls on cold start. | Series are fetched concurrently with a thread pool. |
| Diagnostics | No goodness-of-fit numbers on the historical path; no forward curve or discount factors anywhere. | `RMSE` column on historical factors; `fit_stats()` (`sse`, `rmse`, `r_squared`, `decay_at_bound`); `forward_rate()` and `discount_factor()`. |
| Extensibility | Everything hard-wired to 4 parameters. | Generic seam (`param_names`, `n_linear`, `basis`, `_forward_basis`); `SvenssonModel` added on top of it as proof. |
| Global side effects | `warnings.filterwarnings('ignore')` executed at import in five modules, silencing warnings for every downstream user; synthetic data reseeded the **global** NumPy RNG; a `print()` fired on package import when ipywidgets was missing. | Removed; warning suppression is scoped to the `curve_fit` call; synthetic data uses a local `default_rng`. |
| Tests | Two assertions were mathematically wrong (see §4). Coverage config pointed at a non-existent package (`nelson_siegel_model`). No CI. | Tests corrected; 34 new tests; coverage target fixed; GitHub Actions workflow added. |
| Hygiene | A compiled `.pyc` was committed; `datetime.utcnow()` (deprecated); JS Parameter Lab made an HTTP round-trip for every slider tick. | `.pyc` removed from the index; `datetime.now(timezone.utc)`; slider curve computed client-side. |

Result: 79 tests passing (was 43/45), historical fit path unchanged in cost
(~30 ms for 10 years), single-curve fit ~5 ms, Svensson ~0.3 s.

## 2. Efficiencies found

### 2.1 Implemented in this branch

1. **No second download for tau.** `YieldCurveAnalyzer._estimate_global_tau(bond_type, data=...)` now accepts the frame the caller already has. Before, every cold `analyze_historical_factors` call fetched the bond's default 10-year window a second time just to read the last row.
2. **Memoised downloads.** `BaseDataDownloader.download` caches by resolved `(start, end)`; `clear_cache()` on downloaders and `DataManager`. Returned frames are copies so callers cannot corrupt the cache.
3. **Concurrent FRED fetch.** `_download_from_fred` is shared by both downloaders (was duplicated) and fans series requests out over a small thread pool. Per-series failures are logged and skipped as before.
4. **One data manager in the webapp.** `app.config["DATA_MANAGER"]` is now `analyzer.data_manager`, so snapshot, tau estimation, history and warm-up share the cache.
5. **Grouped OLS via `np.unique(axis=0)`.** The NaN-mask grouping in `_batch_solve` replaces the hand-rolled bit-packing (which would have silently overflowed past 64 maturity columns). Same complexity, fewer moving parts, and it now also returns per-row SSE for free.
6. **Client-side Parameter Lab.** The sliders previously POSTed to `/api/curve` on every debounced tick even though the JS already computed the loadings for the decomposition traces. It now evaluates the curve locally; the endpoint stays for API users.

### 2.2 Recommended, not implemented (out of scope or needs a product decision)

1. **Disk cache for FRED frames** (`.cache/*.parquet`). The design spec already deferred this. It would make cold starts instant across process restarts; requires a decision on cache location and staleness policy.
2. **Warm-up window vs request window.** The cache key is the exact `(start, end)`, so a user asking for 9 of the 10 warmed years still triggers a fresh compute. Slicing a superset frame from the cache would remove most cache misses. Small change in `_get_cached_factors`; deferred because it changes the cache-key contract that tests pin down.
3. **Weekly resampling before download.** FRED supports `frequency="w"` server-side; requesting weekly data directly would cut payload size ~5x for long ranges.
4. **`ThreadPoolExecutor` in `compare_curves`** is now mostly redundant because both fits are ~15 ms; it is harmless and kept.
5. **Timing-based tests** (`test_analyze_historical_factors_speed_under_one_second`, the two `/api/compare` timing tests) will be flaky on slow CI runners. Consider marking them `slow` or replacing with call-count assertions (the cache tests already do this).

## 3. Curve construction model: what changed and why

### 3.1 Profile-likelihood fitting (`NelsonSiegelModel.fit`, default `method="profile"`)

The NS family is linear in the betas once tau is fixed. The fitter now:

1. evaluates a log-spaced grid of 80 tau values within the model's tau bounds (capped to `[0.05, 30]` years when unbounded), solving the betas by least squares at each point;
2. takes the best few **local minima** on the grid and refines each with a bounded Brent search inside its grid cell (Svensson: Nelder-Mead in log-decay space);
3. keeps the lowest-SSE candidate; if the closed-form betas violate the model's beta bounds, falls back to a bounded `curve_fit` warm-started from the profile solution (`fit_stats()["method"] == "profile+curve_fit"`).

The tau search range is also intersected with the **identifiable range** implied by the data: the curvature loading peaks at `t ≈ 1.8·τ`, and that peak must lie inside `[t_min, t_max]` (`hump_location_factor = 1.8`; set to `None` to disable). Without it, the synthetic TIPS snapshot (maturities 5-30y) "optimised" to `τ = 0.12` with slope `+477%` and curvature `−500%`, a collinear blow-up that shaves a bp of RMSE while destroying interpretability. The rule is standard practice (Diebold-Li pin λ so the hump sits at 30 months for exactly this reason). `decay_at_bound` reports when the constraint binds.

Why the multi-start step matters: when curvature is small the profile SSE has several shallow minima in tau. Refining only the best grid cell picked the wrong one on ~3% of a synthetic panel (curvature correlation 0.947 vs truth); with multi-start it is 0.9999+.

Validated properties (tests in `tests/test_model.py::TestProfileFit`):
- exact recovery on noiseless data (tau to 1e-4);
- SSE never worse than `curve_fit` on 10 random noisy curves;
- deterministic (no dependence on an initial guess);
- respects tau bounds; constrained SSE never below unconstrained.

### 3.2 Panel tau for the historical path

`_estimate_global_tau` profiles the **pooled** SSE across up to 48 evenly spaced historical curves, within the same identifiable tau range as the single-curve fitter. This is the standard "one lambda for the panel" Diebold-Li estimate, and it is what the existing closed-form historical fit implicitly assumes. On the synthetic Treasuries tau moves from `1.49` (single day) to `1.58`; on synthetic TIPS from the optimiser bound (`10.0`) to `2.78`, the lower edge of the identifiable range for a 5-30y panel (flagged, and expected for that log-shaped synthetic curve). Cost is ~10 ms.

### 3.3 New curve outputs

- `forward_rate(t)`: instantaneous forward `f(t) = d[t·y(t)]/dt`, closed form `β0 + β1·e^{-t/τ} + β2·(t/τ)·e^{-t/τ}` (plus the Svensson term). Verified against a numerical derivative to 1e-8.
- `discount_factor(t) = exp(-t·y(t))`, treating yields as continuously compounded zero rates. This assumption is documented; par-yield inputs (FRED constant-maturity series are par yields) would need bootstrapping first, see §5.
- `fit_stats()`: `sse`, `rmse`, `r_squared`, `n_obs`, `method`, and `decay_at_bound`, which flags a weakly identified tau. The webapp shows R² and the flag next to RMSE, plots the forward curve, and reports tau and mean RMSE on the historical tab.

### 3.4 Behavioural changes to be aware of

- `fit()` results differ from the old `curve_fit` results wherever the old optimiser had not converged. On well-identified curves the difference is below 1e-6 in yield units.
- Historical factor frames gain an `RMSE` column (decimal units). Existing column names are unchanged.
- `compare_curves()["correlations"]` no longer includes `Tau` (it was always `NaN` under a fixed tau).
- `analyze_single_curve()` gains `fit_stats` and `smooth_forward`.
- Synthetic data values changed (local RNG instead of `np.random.seed`); they remain deterministic.

## 4. Test corrections

Two pre-existing failures were wrong expectations, not model bugs:

1. `test_fit_basic_case` asserted `|tau − 2.0| < 0.5` on five noisy points. A dense grid search shows the least-squares optimum for that exact sample is `tau = 2.518`; the old optimiser happened to return it too. The test now checks the fit's SSE is no worse than at the true parameters.
2. `test_treasury_model_fitting` asserted `Slope < 0` for an **inverted** curve. In Nelson-Siegel `y(0) = β0 + β1`, so an inverted curve has `β1 > 0` (the app's own "Learn" tab says so). The assertion is flipped and now also checks `y(0.25) > y(30)`.

## 5. Is the project suitable for adding more models?

**Yes, with the seam introduced here, for the parametric family. Partially, for non-parametric and dynamic models.**

### What is now in place

`NelsonSiegelModel` is a generic "linear-in-betas given decays" fitter. A new model in the family needs only:

| Hook | Purpose |
|---|---|
| `param_names`, `n_linear`, `factor_labels` | parameter layout |
| `basis(maturities, *decays)` | design matrix for yields |
| `_forward_basis(maturities, *decays)` | design matrix for forwards |
| `model_function(t, *params)` | vectorised evaluation (used by `predict` and the `curve_fit` fallback) |
| `_decays_admissible(decays)` (optional) | exclude degenerate decay combinations |

`SvenssonModel` (6 parameters, two decays) is implemented this way in ~60 lines and passes exact-recovery, nesting, forward-rate, and fixed-decay tests. Candidates that drop in with the same effort:

- **Björk-Christensen** (5 parameters, adds `f1(t, τ/2)`), **Bliss** (NS with separate decays for slope and curvature), **Diebold-Li fixed-λ** (already available as `fit_fixed_tau`).
- **Arbitrage-free NS (Christensen-Diebold-Rudebusch)**: same loadings plus a deterministic yield-adjustment term that depends on the factor covariance; the cross-section fit fits the seam, the covariance estimation needs a time-series step.

### What would need new infrastructure

- **Spline / bootstrap models** (cubic or B-spline discount curves, Fisher-Nychka-Zervos smoothing splines, Monotone-convex): the objects are knots and discount factors, not betas and decays. They should live in a separate `SplineCurve` class behind a small shared protocol (`fit`, `predict`, `forward_rate`, `discount_factor`, `fit_stats`), which the current class already satisfies informally. Recommend formalising that protocol before the second non-NS model.
- **Dynamic / state-space models** (Diebold-Li AR(1) on factors, Kalman-filtered DNS/AFNS): need the factor history produced by `analyze_historical_factors` plus a forecasting layer. `analysis.py` is the natural home; nothing in the current code prevents it.
- **Coupon-bond inputs**: today every input is a zero/par yield. Fitting to bond prices (the standard for Svensson at central banks) requires cash-flow schedules and a price objective; the discount-factor helper is the first building block.

### Where the app is still NS-specific

- `webapp/app.py::_factors_in_percent` and the JS metric tiles assume exactly `Level/Slope/Curvature/Tau`. A `model=` query parameter on `/api/fit` and a generic factor table in the UI are the two changes needed to expose Svensson in the Studio.
- `analysis.py::_batch_fit_factors` and `_panel_profile_tau` call `NelsonSiegelModel.basis` directly. Parameterising them by model class is a mechanical change once a second model is wanted on the historical path.

### Recommendation

1. ~~Expose `SvenssonModel` through `/api/fit` and the Curve Fitter tab.~~ **Done** (follow-up commit): `/api/models` lists registered models with factor metadata; `/api/fit` and `/api/snapshot` accept `model`; `/api/curve` evaluates Svensson when `beta3`/`tau2` are supplied; the Studio has a model switch on the Curve Fitter and Parameter Lab and renders factor tiles generically from `factor_list`.
2. ~~Formalise a `CurveModel` protocol before adding a spline model.~~ **Done**: `nelson_siegel.model.CurveModel` (a `runtime_checkable` `typing.Protocol`) plus `FactorMeta`, `MODEL_REGISTRY`, `get_model_class`, `make_model` and `list_models`. A test documents the minimal surface a third-party (e.g. spline) model must provide.
3. ~~Add a `DynamicNelsonSiegel` forecaster.~~ **Done**: `nelson_siegel.dynamic` implements the Diebold-Li two-step model (random walk / AR(1) per factor / VAR(1), OLS closed form) with iterated forecasts, forecast-error bands, curve projection through the model loadings, persistence and half-lives, a stationarity check, and a rolling-origin `backtest()` against realised factors and yields. Exposed via `YieldCurveAnalyzer.forecast_factors` / `backtest_factor_forecasts`, `/api/forecast`, `/api/backtest`, and a Forecast panel on the Historical tab. Works on Svensson factor frames as well (`model_cls=SvenssonModel`).
4. The historical path (`_batch_fit_factors`, `_panel_profile_tau`) is still Nelson-Siegel only; parameterising it by model class is the next mechanical step if Svensson factor histories are wanted.

### UI/UX changes in the follow-up commit

- Model switch (Nelson-Siegel / Svensson) on the Curve Fitter and Parameter Lab; factor tiles and badges (model, RMSE, R², point count, "τ at search bound") rendered from the API's metadata.
- Paste box for quotes (`2Y 4.30`, `3M, 4.95%`, tab/comma separated), Enter-to-fit in any cell, loading states on every action button, "Use last fit" to push fitted parameters into the sliders, optional forward curve in the lab.
- Quick-range chips (1Y/3Y/5Y/10Y) on Historical and Compare, a per-date fit-RMSE chart and τ / mean-RMSE tiles on Historical, a curvature-correlation tile on Compare, CSV export on all three result views.
- Settings (bond type, model, ranges) persist in `localStorage`; `Alt+1..5` switch tabs; `aria-pressed`/`aria-busy` on controls; mobile layout with a horizontal nav; reduced-motion respected; favicon.
- Offline resilience: when the optional `plotly` Python package is installed the Studio serves plotly.js locally instead of the CDN; when the library cannot load, chart panels say so instead of staying blank (numbers and CSV export keep working).
- Learn tab: fixed the τ/λ notation clash (maturity is now `t`, decay `τ`), added Svensson, forward-curve and fit-quality explanations.

## 6. Other observations (not changed)

- `ARCHITECTURE.md` and `docs/README.md` list files that do not exist (`test_interactive.py`, `docs/model_theory.md`, `docs/api_reference.md`, `docs/interactive_guide.md`) and omit the webapp package and `tests/test_webapp.py`.
- Root-level `nelsonsiegelmodel.py` and `nelson_siegel_historical_analysis.py` duplicate `examples/legacy_nelson_siegel.py`; they import `yfinance`/`ipywidgets` unconditionally and are not covered by tests. Candidates for removal.
- `pyproject.toml` declares `requires-python >= 3.8`, but current NumPy/pandas releases need 3.10+; the CI matrix added here tests 3.10-3.12. `authors` still carries placeholder contact details.
- `interactive.py` annotated methods with `widgets.Widget` at class-definition time, so importing it without ipywidgets raised `NameError`. Fixed in this branch with postponed annotations; `nelson_siegel.HAS_INTERACTIVE` now reflects whether ipywidgets is actually installed. The widget classes themselves remain untested.
- The Learn tab uses τ for maturity and λ for decay while the sliders and API use τ for decay. Cosmetic, but confusing for the educational audience.
- `requests`, `quandl`, `alpha-vantage` and `yfinance` are declared but unused by the package.
